# AGENTS.md

## Cursor Cloud specific instructions

### What this project is
Fastest-lap is a C++ vehicle-dynamics simulator (optimal lap-time, G-G diagrams,
circuit preprocessing) exposed through a Python API. There is no long-running
server: the "application" is the shared library `libfastestlapc.so` driven either
by the C++ Google Test suites or by the Python examples under
`examples/python/`. Build system is CMake (see `README.md` for the canonical
`mkdir build && cd build && cmake .. && make && ctest` flow).

### Toolchain gotcha (important)
`/usr/bin/c++` and `/usr/bin/cc` default to clang on this image, but the project
must be built with GCC (clang can't find libstdc++ here and the code targets
GCC). The alternatives are already pointed at GCC in the snapshot via
`update-alternatives --set c++ /usr/bin/g++` and `... cc /usr/bin/gcc`. If a
fresh image ever reverts this, re-run those two commands before configuring.

### Building
The fully-built `build/` directory is baked into the VM snapshot (it is
git-ignored), so a normal session does NOT need to rebuild. To rebuild the
project itself after changing `src/`:
```
export LD_LIBRARY_PATH=/workspace/build/lib:/workspace/build/thirdparty/lib:$LD_LIBRARY_PATH
cmake --build /workspace/build -j$(nproc)
```
Modern GCC (13.x) needs `<utility>` for `std::as_const`, which the source relies
on transitively. The generated `build/**/flags.make` for the `src/` targets have
`-include utility` appended so the existing `build/` compiles. For a
from-scratch configure, pass it explicitly:
`cmake .. -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_FLAGS="-include utility"`.

### Rebuilding third-party from scratch (only if `build/` is wiped)
`cmake ..` downloads and compiles third-party libs (lion-cpp -> Ipopt, LAPACK,
CppAD, tinyxml2, logger-cpp, googletest). This is slow (~10 min) and has two
upstream-drift traps that are already worked around inside the baked `build/`:
- CppAD's git clone can fail transiently and lion's build swallows the error,
  leaving `lion/thirdparty/include/cppad` missing. If so, re-clone
  `https://github.com/coin-or/CppAD.git` at tag
  `6856fdde535d2a7634a6fc36d8787a72166dce91` and `cmake install` it so its
  headers land under `build/thirdparty/include/lion/thirdparty/include/cppad`.
- logger-cpp is pinned to `main`, which has moved past what pinned lion-cpp
  expects (it now wraps everything in `namespace logger`, breaking lion's global
  `out`). Use the pre-namespace `logger.h`/`logger.hpp` pair from commit
  `db67111^` (`83dc175`) and make it modern-GCC clean (`sprintf_s` -> `sprintf`,
  unqualified `min` -> `std::min`).

### Running tests
`ctest` (from `build/`) runs the five suites. Individual suites can be run
directly, but they must be launched from their own build dir because they read
`./data` and `./database` symlinks:
```
export LD_LIBRARY_PATH=/workspace/build/lib:/workspace/build/thirdparty/lib:$LD_LIBRARY_PATH
cd /workspace/build/src/test/vehicles && ./vehicles_test
```
`applications_test` is very heavy (302 cases incl. full Ipopt optimal-laptime
sims) and can take tens of minutes; the other four suites finish in seconds.

### Running the Python API / examples
`examples/python/fastest_lap.py` is generated by CMake with an absolute path to
`libfastestlapc.so` baked in (it is untracked — do not commit it). It imports
`matplotlib` and `numpy` at import time. Run examples with:
```
export LD_LIBRARY_PATH=/workspace/build/lib:/workspace/build/thirdparty/lib:$LD_LIBRARY_PATH
PYTHONPATH=/workspace/examples/python python3 your_script.py
```
